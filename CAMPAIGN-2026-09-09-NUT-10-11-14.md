*2026-09-09. Amperstrand internal. Everything below is documented in this

## What we did

Started from one question — the framework doc's "NEXT — highest value" row:
8 behavioral divergences between cdk and nutshell documented in cdk#2252.
Ended with: a frozen-prediction probe, a measured 12-cell matrix across
four implementations and six versions, two upstream stories corrected, a
security triage, a wallet-side emission census, a community census reaching
back to 2023, and standing automation that turns the whole exercise into a
weekly one-liner.

## What we found (ranked)

1. **The HTLC Sender Pathway is cross-implementation incompatible —
   proven, not argued.** cdk rejects refund witnesses whose `preimage`
   field is absent or JSON-null (deserializing them as `P2PKWitness`),
   accepts any present string without checking it; nutshell accepts
   absent/null, rejects wrong values. Accepted-shape intersection = only
   the    true preimage, which refund senders never hold. Every major TS
   wallet (cashu-ts, cashu-cf) emits the shape cdk rejects. This blocks
   Spilman-channel failure recovery (nuts#296) outright. *Preview-measured
   caveat (2026-09-09):* nutshell-main (next release) drops the
   wrong-preimage check, so post-release the dummy-preimage shape works on
   both mints — the hard incompatibility is specific to the current image
   pair; the d6 issue carries the updated intersection table.
2. **Both references violate NUT-11's merged MUSTs** (duplicate tags;
   n_sigs > key pool — nuts#358, Jun 2026, vectorless). Convergence went
   the wrong way: the ecosystem's spread is now DotNet stricter-than-MUST
   ↔ Nutmix looser-than-MUST (over-accepting invalid HTLC SIG_ALL spends),
   with the references in a lenient middle that the printed spec forbids.
   *Temporary, it turns out:* nutshell-main (42 commits unreleased at
   audit time — the 0.20.3 image is a faithful build of the Jul-22 tag,
   which predates #1008's Aug-11 merge) already enforces both MUSTs. The
   next nutshell image flips SEVEN cells (preview-measured, run
   20260909-224356): d2/d3/d4/d5 → REJECT and d6c/d7/d8 → ACCEPT — the
   #1008 rewrite silently drops two hardening checks the released image
   has, so the release loosens as well as tightens — and nutshell-main
   matches the cdk#2252 table on all 8 divergences (the table was early,
   not wrong). That leaves cdk the lone lenient reference on the MUST
   cells; the weekly matrix exists to catch exactly this.
3. **Two silent softforks dated.** nutshell's strictness flip (d1/d7/d8)
   shipped by 0.20.2 (≡ 0.20.3 on all 12 cells; #1008 merged Aug 11);
   cdk's d6 regression window is **0.16.0 → 0.17.0** (checker had 0.16.0
   passing; 0.17.0/0.17.6/0.18.0 measured identical, including the full
   witness-shape frontier — Docker Hub publishes no 0.16.x, so 0.17.0 is
   the tightest available pin). Both flips shipped without issue,
   changelog line, or test failure — expected-reject suites pass on any
   rejection, including rejections for the wrong reason.
4. **The community's recorded direction matches our POSITION doc.**
   a1denvalu3 on nuts#358 (Apr 2026): mints treat malformed as
   anyone-can-spend, wallets reject — the same mint-lenient/wallet-strict
   split we reached independently for NUT-00 (duty-follows-issuance). The
   merged MUST text binds the mint instead; nobody implements either half.
5. **Security shape:** no cell lets an attacker spend validly locked money
   under today's kinds. The malformed-lock theft vector (recipient shown
   "P2PK-locked" money with garbage in `data`) was **measured dead on cdk
   0.18.0** — cell d1b: REJECT 20008, refuting cdk#2252's fallback claim in
   the safe direction; d1's residual exposure is unknown-kind secrets only
   (future kinds — channels). Refund-path incompatibility (d6) is
   loss-shaped and total. The previously-open wallet-parse question is
   answered: no interpretation split among the majors (cashu-ts reads
   first-tag via `.find()`; nutshell wallet shares the mint's core parser);
   the residual d2 hazard is the accept/reject split, not divergent reads.
6. **Spec hygiene:** NUT-10 and NUT-11 contradict each other on tag arity
   (since Dec 2025, #320 vs 2023's original); NUT-14's preimage
   optionality is unstated; the error-text census shows both mints
   returning misleading diagnostics at exactly the moments clients need
   them (cdk's 50000 "Secret is not a HTLC secret" names the wrong object).

## How we know

Frozen-prediction A/B probing (`conformance/ab_probe_p2pk_htlc.py`): mint
regular proofs → blind-swap into divergence-triggering secrets (verifier-
only coupling) → attempt the discriminating spend; controls first;
identity via /v1/info; repeat runs for stability; mismatches analyzed
version-first. All cells stable across every run. Evidence:
`conformance/reports/ab-*.json|.log`, `conformance/runs/version-matrix-*`.
Two frozen predictions were refuted mid-campaign (d6b, d6c) and left in
place — the refutations were the two sharpest findings.

## The infrastructure turn

`conformance/version_matrix.py` + run registry + CI workflow: any set of
docker-tag / git-ref / live-URL arms, one probe pass, intra-run version
diffs, inter-run drift diffs. First runs produced findings #3 above in
minutes. Operational archaeology encoded so it never needs re-learning:
nutshell's env renames and missing ENTRYPOINT, cdk's 0.17/0.18 config
split (`CDK_MINTD_LN_BACKEND` vs `config init`), colima `$HOME` mounts,
rate limiter, bark SSH shim. Docs:
`conformance/AUTOMATED-CROSS-IMPLEMENTATION-TESTING.md`.

## Where this connects to prior work

The NUT-00 campaign's class-generalization held up exactly: dual
representations (witness envelope shape, tag arity), verifier-only
coupling, holder discovers at first spend, specs descriptive-where-they-
should-be-normative, vectors missing where MUSTs exist. The migration-
softfork corollary acquired two dated instances. The error-code registry
issue gained a census. And the community independently converged on our
split-handling position — the strongest external validation yet for the
nuts-PR strategy (wallet-side MUST + mint-side leniency + vectors).
