# NUT-10/11/14 Cross-Implementation Divergences

Source: [CDK #2252](https://github.com/cashubtc/cdk/issues/2252) + cashu-cf audit (2026-07-26)

## Overview

NUT-10 (spending conditions), NUT-11 (P2PK), and NUT-14 (HTLCs) define how Cashu proofs can be locked with spending conditions. The three major implementations (CDK, Nutshell, cashu-cf) agree on the core protocol but diverge on 8 edge cases.

These divergences mean a token spendable at one mint may be bricked at another. This database documents each divergence with the spec reference and each implementation's behavior.

## Divergence Table

| # | Issue | CDK (Rust) | Nutshell (Python) | cashu-cf (TypeScript) | Spec reference | Resolution |
|---|---|---|---|---|---|---|
| 1 | Malformed/unknown-kind NUT-10 secrets | anyone-can-spend fallback | fail-closed (rejected) | **CDK-aligned**: `tryParseSecret` returns null → regular proof | NUT-10 Caution: "may be treated as regular anyone-can-spend" | Unresolved — spec permits both |
| 2 | Duplicate tags | first occurrence wins | rejected as malformed | **Nutshell-aligned** (pubkeys only): `Set` dedup check; other tags use first-match | NUT-11 L85: "MUST be rejected" | cashu-cf partial; should reject ALL duplicate tags |
| 3 | `n_sigs` exceeding available pubkeys | not validated (refund path usable) | rejected upfront (blocks refund too) | **Nutshell-aligned**: `pubkeys.length < nSigsRequired` → throw | NUT-11 L87: "MUST be rejected" | CDK should align to Nutshell |
| 4 | Empty multi-value tag `["pubkeys"]` | accepted (empty key list) | rejected (must have ≥1 value) | **CDK-aligned**: empty → 0 pubkeys → anyone-can-spend (primary key from `secret.data` still provides security) | NUT-11 (implied) | Needs spec clarification |
| 5 | HTLC hash hex case sensitivity | mixed/upper-case accepted | lowercase only | **Nutshell-aligned**: `normalizeHex()` lowercases | NUT-14: lowercase specified | CDK should align to Nutshell |
| 6 | HTLC refund via SIG_INPUTS with sig-only witness | rejects (wrong witness type) | accepts (preimage optional in refund) | **Nutshell-aligned**: refund path checks sigs only, no preimage required | NUT-14 (implied) | CDK should align to Nutshell |
| 7 | Duplicate signatures from same key | errors with `DuplicateSignature` | ignores extra signature | **CDK-aligned**: `Set` check throws | NUT-11 (unspecified) | Unresolved — spec doesn't address |
| 8 | Witness on plain (non-NUT-10) secret | rejects with `IncorrectWitnessKind` | accepts and ignores | **Nutshell-aligned**: `if (!secret) return;` — witness ignored | NUT-10 (unspecified) | Unresolved — spec doesn't address |

## Other Divergences (beyond CDK #2252)

### ISSUE-023: NUT-04 mint output validation (cashu-cf, FIXED)

- **Was**: `validateAmountTotal(output, quote.amount, '===')` — strict equality, rejects partial mints
- **Spec**: NUT-04 L83: "MUST NOT issue ecash whose total output amount exceeds `amount_paid - amount_issued`" — permits partial mints
- **Fixed**: Changed to `<=` with `amount_paid - amount_issued` invariant (commit a754f9a)
- **Found by**: greatspectations — the `// NUT #04:` verbatim quote at the validation line mechanically surfaced the deviation
