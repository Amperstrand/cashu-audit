## 2. Findings

### Finding 1: V4 Token Decoding Fails (HIGH)
- **Severity**: HIGH
- **Location**: gonuts-tollgate/cashu/cashu.go:401-426 (DecodeTokenV4)
- **Description**: Cashu wallet 0.20.0 defaults to V4 tokens (`cashuB` prefix, CBOR format). The `DecodeTokenV4` function fails to decode them. Root cause likely: `cbor.Unmarshal` uses `json` struct tags on `TokenV4` struct, which may not match CBOR encoding from modern wallets.
- **Evidence**: KVM QA test — POSTed valid `cashuB...` token to backend, received `"invalid token: invalid V3 token"` (V4 error masked, V3 fallback also fails)
- **Impact**: Any user with a modern Cashu wallet (V4 default) cannot pay a TollGate router
- **Recommendation**: Fix CBOR decoding in gonuts OR migrate to CDK (#305) which has native V4 support

### Finding 2: Error Diagnostics Mask V4 Failure (MEDIUM)
- **Severity**: MEDIUM
- **Location**: gonuts-tollgate/cashu/cashu.go:175-186 (DecodeToken)
- **Description**: `DecodeToken` tries V4 first, then V3 on failure. The V4 error variable is overwritten by the V3 error, so users see "invalid V3 token" even when their input was V4. This makes debugging extremely difficult.
- **Code**:
  ```go
  token, err := DecodeTokenV4(tokenstr)  // V4 error assigned to err
  if err != nil {
      tokenV3, err := DecodeTokenV3(tokenstr)  // err REASSIGNED — V4 error lost
      if err != nil {
          return nil, fmt.Errorf("invalid token: %v", err)  // Only V3 error surfaces
      }
  }
  ```
- **Recommendation**: Log the V4 error before trying V3 fallback. Return a combined error if both fail.

### Finding 3: Fund() Uses V4-Only Path (MEDIUM)
- **Severity**: MEDIUM
- **Location**: merchant.go:1085-1116 (Fund)
- **Description**: `Fund()` calls `cashu.DecodeTokenV4(cashuToken)` directly, skipping the generic `DecodeToken` that includes V3 fallback. If someone tries to fund with a V3 token via CLI, it fails.
- **Also**: Stale comment at line 1089 says "cashu tokens typically start with 'cashuA'" — V4 starts with 'cashuB'
- **Recommendation**: Use `cashu.DecodeToken` (generic) instead of `cashu.DecodeTokenV4`

### Finding 4: Bilateral V4 Incompatibility (INFO)
- **Severity**: INFO
- **Location**: tollwallet.go:173,222,249 vs merchant.go:457
- **Description**: TollGate creates V4 tokens for sending (`NewTokenV4`) but cannot receive V4 tokens (DecodeTokenV4 broken). A TollGate sending a payment to another TollGate would produce a V4 token that the receiver can't process.
- **Recommendation**: Fix V4 decoding, or use V3 for inter-TollGate payments until CDK migration

## 3. Code Path Analysis

### Token Reception Flow (Payment)
```
POST :2121/ → extractCashuToken(body) → string
            → merchant.PurchaseSession(cashuToken, mac)
            → cashu.DecodeToken(cashuToken)     [gonuts: V4→V3 fallback]
            → tollwallet.Receive(token)
            → wallet.Receive(token, swap)        [gonuts: mint HTTP calls]
```

### Token Creation Flow (Send)
```
merchant.CreatePaymentToken → tollwallet.Send(amount, mint, fees)
                            → wallet.Send()      [gonuts: split proofs]
                            → cashu.NewTokenV4(proofs, mint, unit, includeFees)
                            → returns cashuB... token
```

### Token Funding Flow (CLI)
```
merchant.Fund(cashuToken) → cashu.DecodeTokenV4(cashuToken)  [V4 ONLY — no fallback]
                         → tollwallet.Receive(parsedToken)
```
