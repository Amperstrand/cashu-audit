## CORRECTION: Previous "V4 Broken" Finding Was Invalid

Previous testing (2026-07-28 KVM QA) reported V4 token decoding failure. Root cause investigation revealed:

1. Cashu CLI `send` command outputs token on line 1 and "Balance: X sat" on line 2
2. Bash `$(...)` captured BOTH lines → token corrupted with trailing text
3. Corrupted token sent via `curl -d "$CORRUPTED_TOKEN"` → decode failed
4. Error "invalid V3 token" surfaced (V4 error masked by V3 fallback)

Direct testing of `cashu.DecodeTokenV4()` on gonuts v0.10.0 (commit ae6963f):
```
DecodeTokenV4 success! MintURL: http://10.99.99.2:8383, Unit: sat
TokenProofs count: 1
```

**Issue #326 closed as invalid.**

## Remaining Findings

### Finding 1: DecodeToken Error Masking (WARN)
- V4 error overwritten by V3 fallback error. Users see "invalid V3 token" for V4 input.
- Recommendation: Log V4 error before trying V3.

### Finding 2: Fund() Uses V4-Only Path (WARN)
- `merchant.go:1101` calls `DecodeTokenV4` directly, no V3 fallback.
- Fix: Use generic `DecodeToken`.
- Tracked in: #325

### Finding 3: Stale Comment (LOW)
- `merchant.go:1089`: "cashu tokens typically start with 'cashuA'" — V4 starts with 'cashuB'.
