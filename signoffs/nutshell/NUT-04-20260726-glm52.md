## Observations (non-blocking, no spec impact)

1. **Invoice case normalization**: ledger.py:371 `request = invoice_response.payment_request.lower()`. The code comment (L369-370) acknowledges this is Lightning-specific ("might not work with other methods"). Not a spec issue for bolt11-only support.

2. **Balance limit check**: ledger.py:346-349 checks `mint_max_balance` before creating a quote. This is an operational guard not required by NUT-04 but sound for mint solvency.

3. **Backend rate-limiting on payment check**: `get_mint_quote` (ledger.py:420-430) uses `try_update_mint_quote_last_checked` with `mint_quote_backend_check_rate_limit` to avoid hammering the Lightning backend on every poll. Spec-compliant (response still reflects current state; just may be slightly stale).

4. **Internal settlement optimization**: When a melt quote's payment request matches a mint quote, Nutshell settles internally with zero fees (ledger.py:950-1025, `melt_mint_settle_internally`). This is a UX optimization for circular payments, not a NUT-04 requirement.

5. **Batch mint (NUT-29)**: `mint_batch()` (ledger.py:543-669) and `POST /v1/mint/bolt11/batch` (router.py:451-466) extend NUT-04 for batch operations. Validates quote consistency (same method, same unit), prevents duplicate quotes, enforces amount matching. Uses sorted quote IDs for deterministic lock ordering (write.py:196) to prevent deadlocks.

6. **Redis cache on mint endpoint**: router.py:504 `@redis.cache()` on `POST /v1/mint/bolt11`. This is a NUT-19 feature; without client cache-control headers it does not cache mutating responses. Does not affect NUT-04 correctness.

7. **Wallet-side stale-response handling**: `MintQuote.check_stale_and_from_resp_wallet` (base.py:569-631) implements the wallet-side MUSTs (spec L85): rejects responses with lower `updated_at`, lower `amount_paid`, or lower `amount_issued` than locally stored values. Correctly uses `<` (strict less-than) comparisons.

## Verdict

**PASS.** Nutshell's NUT-04 implementation satisfies every MUST in the specification:

- **Quote creation**: Correct endpoints (`POST /v1/mint/quote/bolt11`, `GET .../{quote}`, `POST /v1/mint/bolt11`), UUIDv7 quote IDs with 74 CSPRNG bits, quote ID independent of payment request.
- **Accounting fields**: `amount_paid`, `amount_issued`, `updated_at` are present in all quote responses. Values are always non-negative. `amount_issued` never exceeds `amount_paid`. State transitions correctly update accounting fields.
- **Mint execution**: Quote must be paid, not issued, not pending, not expired. Output amount must match quote amount (strict `==`, which is stronger than spec's `<=`). Blind signatures issued atomically with row-locked state transition.
- **Security**: Quote ID is secret (random, not derivable). NUT-20 pubkey locks enforced. Concurrent mint prevented by PENDING state lock.
- **NUT-06 settings**: Method-unit pairs correctly advertised with limits.

**3 WARNs** (non-blocking):
1. `updated_at` uses 1-second resolution (`int(time.time())`) — not strictly monotonic within the same second. Practically harmless due to external payment latency.
2. Partial minting not supported (`==` instead of `<=`) — stricter than spec, blocks partial-mint use case. Not a MUST violation.
3. No custom payment method support — only `bolt11` via hardcoded routes. Feature absence, not a violation.

**0 FAILs. No spec MUST violations found.**
