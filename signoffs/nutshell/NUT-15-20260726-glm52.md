## Additional Observations (non-spec)

### MPP amount transport design (no separate DB column)
The `MeltQuote` database model (`core/base.py:292-308`) does **not** store `mpp_amount` or `is_mpp`. Instead, the partial amount is normalized into the quote's native `unit` and stored in the existing `amount` column. At payment time, the Lightning backends reconstruct the partial msat amount by comparing the stored `amount` (converted to msat) against the decoded BOLT11 `amount_msat`. A difference signals a partial payment.

This design is correct because `validate_payment_quote` (ledger.py:723-731) enforces at quote creation that the backend's payment-quote amount equals the requested `mpp_amount` in msat, so the round-trip through the unit conversion is lossless for whole-msat values. One benign edge case: if a wallet requests a partial amount exactly equal to the full invoice amount, the backend treats it as a normal (non-MPP) payment — which is functionally identical to a successful full MPP payment, so no behavior diverges.

### Backend capability flag wiring
`supports_mpp` is sourced from settings for the real Lightning backends:
- `mint_lnd_enable_mpp` (default True) → lndrest.py:52, lnd_grpc.py:54
- `mint_clnrest_enable_mpp` (default True) → clnrest.py:47

Both default to enabled, meaning a Nutshell mint with LND or CLN advertises MPP out of the box. The flag flows from `LightningBackend.supports_mpp` → `Ledger.backends[method][unit].supports_mpp` → `features.add_mpp_features` → NUT-06 info. The same flag gates both advertisement (info) and enforcement (ledger rejection of partial requests for non-MPP backends). Single source of truth — no drift possible.

### Test coverage
`tests/wallet/test_wallet_regtest_mpp.py` exercises a realistic two-mint multimint MPP scenario against a regtest backend: it tops up a wallet, fetches a real invoice, splits it into two partial melts (32 sat each of a 64 sat invoice), and asserts both succeed. The test is gated on the backend actually supporting MPP (`ledger.backends[...].supports_mpp`) and on the wallet's view of mint info (`wallet.mint_info.supports_mpp("bolt11", wallet.unit)`, line 45) — directly validating the N15-R1 advertisement path end-to-end.
