### 5.2 Specific improvements

1. **NUT-00 BDHKE protocol tracing**: The 12 quotes in `b_dhke.py` create a step-by-step trail through the blind Diffie-Hellman key exchange. An auditor can verify each protocol step (blinding → signing → unblinding → verification) by following the quotes in source order. This is materially better than the pre-quote approach where the auditor had to hold the spec open alongside the code.

2. **NUT-04 accounting field invariants**: The 3 consecutive quotes at `ledger.py:387-389` (`amount_paid`/`amount_issued`/`updated_at` requirements) cluster the critical accounting invariants at the point where the MintQuote is constructed, making it trivial to verify all three are satisfied.

3. **NUT-06 field documentation**: The 13 quotes in `mint_info.py` effectively turn the model file into a self-documenting spec reference. Each field's purpose, type, and semantics are documented inline.

### 5.3 Specific regressions / risks introduced

1. **False confidence on unquoted requirements**: The presence of quotes for SOME requirements (e.g., NUT-02 `input_fee_ppk`) may cause an auditor to assume ALL requirements in that area are quoted, missing the unquoted parallel (`final_expiry`). This is a coverage asymmetry risk.

2. **NUT-03 minimal coverage**: With only 1 quote for the entire swap spec, a quote-driven auditor might under-scrutinize the swap flow. The pre-quote audit found 11 MUSTs; only 1 is quoted.

3. **NUT-06 misplaced quotes**: All 13 NUT-06 quotes are in the wallet-side `MintInfo` model, not the mint-side `GetInfoResponse` model that actually produces the API response. An auditor following quotes would examine `mint_info.py` (correct for wallet parsing) but might skip `models/info.py` + `features.py` (where the response is actually built). The pre-quote audit correctly audited the mint-side files.

- **Quote impact**: The inline quote makes the absence of validation more visible. However, this is a serialization invariant, not a runtime MUST — the mint never receives TokenV4 directly (it receives Proof objects via API). Severity remains Low.

## 6. Findings (Consolidated)

### Finding Q-1: TokenV4 same-keyset-ID invariant not validated
- **Severity**: Low
- **Location**: `base.py:1386` (quote), `base.py:1389-1393` (`TokenV4Token`)
- **Quote**: "All proofs in the corresponding `p` array MUST belong to the same keyset ID."
- **Code**: `TokenV4Token` accepts `i: bytes` + `p: List[TokenV4Proof]` with no validation that proofs share the keyset. Grouping is structural in `from_tokenv3` (L1473-1478) but not enforced on deserialization.
- **Impact**: A malformed TokenV4 with mixed keyset proofs would parse without error. The mint API never sees TokenV4 directly (proofs are extracted first), so this is a wallet-layer invariant.
- **Recommendation**: Add a `model_validator` to `TokenV4Token` checking that all proofs are intended for the same keyset. Low priority.

### Finding Q-2: Mint URL trailing-slash normalization not enforced (quote-elevated)
- **Severity**: Medium (elevated from Low by inline quote)
- **Location**: `base.py:1411` (quote), `base.py:1412-1413` (`set_mint`)
- **Quote**: "The mint URL **MUST** be normalized by stripping any trailing slashes (`/`)."
- **Code**: `set_mint(self, mint: str): self.m = mint` — no `rstrip("/")`.
- **Impact**: Tokens received from external sources with trailing slashes in the mint URL are stored verbatim. URL-matching during swap operations may fail.
- **Recommendation**: Change to `self.m = mint.rstrip("/")`. One-line fix. The inline quote makes this omission impossible to overlook.

### Finding Q-3: NUT-02 `final_expiry` guard asymmetry (unquoted parallel)
- **Severity**: Low (unchanged from pre-quote)
- **Location**: `keys.py:100` (quoted `input_fee_ppk` guard), `keys.py:105-106` (unquoted `final_expiry` guard)
- **Description**: The quote at L100 documents the `input_fee_ppk` preimage condition (`> 0` guard), but the parallel `final_expiry` condition at L105-106 uses only `is not None` without the spec's `!= 0` guard. The asymmetry between quoted and unquoted conditions creates a blind spot.
- **Impact**: Negligible (`final_expiry == 0` is unreachable in practice).
- **Recommendation**: Add `and final_expiry != 0` to L105 for spec-exactness. Consider adding a parallel quote for the `final_expiry` condition.

### Finding Q-4: NUT-03 severely under-quoted
- **Severity**: Informational (audit methodology concern)
- **Location**: `ledger.py` swap section (L1330-1396) — only 1 quote at L1353
- **Description**: NUT-03 is the most critical Cashu operation (swap), with 8+ MUST-level requirements. Only the high-level description is quoted. Endpoint format, request/response models, conservation of value, atomicity, and double-spend protection are all unquoted.
- **Impact**: A quote-driven auditor may under-scrutinize the swap flow. The pre-quote audit verified all 11 MUSTs — quotes added no value here.
- **Recommendation**: Add quotes for: endpoint `POST /v1/swap`, request `{inputs, outputs}`, response `{signatures}`, conservation `Σinputs == Σoutputs`.

## 8. Methodology Notes

### Audit approach
1. Read all 6 source files in full (b_dhke.py, keys.py, secp.py, base.py, ledger.py, mint_info.py).
2. Read all 7 NUT specs (00.md through 06.md).
3. Grep for all `# NUT #0[0-6]:` patterns to enumerate quotes.
4. For each quote: verify quote text against spec, then verify code behavior against quoted claim.
5. Identify spec requirements NOT covered by any quote (coverage gaps).
6. Compare findings against pre-quote signoffs.

### Limitations
- This audit focused on the 6 source files specified in the task. Files like `router.py`, `verification.py`, `keysets.py`, `features.py`, and `models/info.py` were referenced via cross-references from the pre-quote signoffs but not re-audited from scratch.
- The ledger.py file (1544 lines) was read in 3 segments (1-500, 500-1099, 1100-1544). All NUT-03/04/05 quotes were verified.
- Wallet-side code (`cashu/wallet/`) was not audited — wallet MUSTs are noted but not verified.
