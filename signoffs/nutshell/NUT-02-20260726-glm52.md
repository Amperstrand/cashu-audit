## Findings

### Finding 1: V2 keyset ID preimage omits `final_expiry != 0` guard
- **Severity**: Low (non-blocking, edge case)
- **Location**: `cashu/core/crypto/keys.py:96-97`
- **Description**: NUT-02 spec L86-87 reference implementation for the V2 keyset ID preimage reads:
  ```python
  if final_expiry is not None and final_expiry != 0:
      keyset_id_bytes += f"|final_expiry:{final_expiry}".encode("utf-8")
  ```
  Nutshell's `derive_keyset_id_v2` (keys.py:96-97) uses only:
  ```python
  if final_expiry is not None:
      keyset_id_bytes += f"|final_expiry:{final_expiry}".encode("utf-8")
  ```
  The `!= 0` guard is missing. If `final_expiry == 0` were passed, Nutshell would include `|final_expiry:0` in the SHA-256 preimage, whereas a spec-strict implementation would omit it — producing different keyset IDs for the same logical inputs.
- **Impact**: Negligible in practice. `final_expiry == 0` means "expired at Unix epoch (1970-01-01)", which is semantically nonsensical for a keyset and would never be configured by an operator. `input_fee_ppk` is correctly guarded with `> 0` (keys.py:92), and that is the field with realistic zero values. No code path sets `final_expiry = 0`: `MintKeyset.__init__` defaults it to `None` (base.py:1015), `rotate_next_keyset` passes the caller value through (keysets.py:102), and `activate_keyset` passes `None` for new keysets (base.py via keysets.py:162). The deviation is unreachable under normal operation but represents a literal spec-reference mismatch.
- **Recommendation**: Align the guard with the spec reference for exactness:
  ```python
  if final_expiry is not None and final_expiry != 0:
  ```
  This is a one-character-class change with no behavioral impact on existing keysets (which never use `final_expiry == 0`).

## Notes

### Scope clarifications
- **Mint vs wallet MUSTs**: NUT-02 contains both mint-side and wallet-side MUSTs. Nutshell functions as both, but this audit focused on the mint surface (the files listed above). Wallet-side MUSTs (e.g., L17 "wallets SHOULD compute the keyset id themselves", L27 "wallets SHOULD prioritize swaps from inactive keysets", L112-114 "wallets should reject keyset ID collisions on import") were not separately audited as they live in `cashu/wallet/`, outside the specified file set.
- **Keyset rotation (L25)**: Spec describes rotation as "generate a new active keyset and inactivate an old one." Nutshell implements this in `rotate_next_keyset` (keysets.py:37-115): creates new keyset with `active=True`, stores it, then sets `selected_keyset.active = False` and persists. Correct, though triggered manually via management RPC, not automatically.

### Cross-reference with prior audits
- The keyset ID derivation functions in `keys.py` were also touched in the NUT-00 audit (N00-R31 short ID). This audit confirms the V2 full-ID derivation (`derive_keyset_id_v2`) and the fee mechanics, which were out of scope for NUT-00.
