## Deviations & Findings

### INFO-1: `amount_paid`/`amount_issued` fields exist but are bolt11-scoped
**Location**: `core/base.py:430-431`; `mint/crud.py:610,640-641,708,726-727`; `mint/migrations.py:1272-1275`

The `MintQuote` model includes `amount_paid` and `amount_issued` fields, and the DB schema has corresponding columns. These were added as part of the NUT-04 bolt11 flow (the spec's "amount paid" / "amount issued" tracking is generic). In the bolt11 flow, `amount_paid` is set to the quote amount when paid and `amount_issued` is set to the quote amount when minted (`core/base.py:652-659`). This infrastructure **could** partially support NUT-25's multiple-issuance model, but without a bolt12 backend, route, or method enum, it is inert for BOLT12 purposes. **No action required** — this is correctly scoped to bolt11.

### INFO-2: `amountless` field exists in management RPC proto
**Location**: `mint/management_rpc/protos/management.proto:164`; `management_pb2.pyi:331`

The management RPC proto defines `bool amountless = 1` in what appears to be a melt-quote-related message. This is unrelated to NUT-25's `options.amountless.amount_msat` (which is a per-request millisatoshis integer for amount-less BOLT12 offers). The proto field is a boolean flag likely used for NUT-05 amountless BOLT11 invoices. **No action required.**

### INFO-3: Consistent with upstream registry
The official NUTs README (`/home/ubuntu/src/nuts/README.md` line for NUT-25) lists only `cdk` and `cashu-ts` as wallet implementations and `cdk-mintd` as the sole mint implementation. Nutshell is **not** listed for NUT-25 in either role. The absence is expected and documented upstream.

## Verdict

**NOT IMPLEMENTED** — NUT-25 (BOLT12 payment method) is entirely absent from Nutshell. No code, routes, models, backends, or feature advertisements exist for the `bolt12` method. The `Method` enum contains only `bolt11`. All 3 explicit MUSTs and 13 structural requirements are non-evaluable (N/A) due to the complete absence of any BOLT12 surface. This is consistent with the upstream NUTs registry, which does not list Nutshell as a NUT-25 implementer. No compliance violations can occur against an unimplemented optional NUT. If BOLT12 support is desired in the future, it would require: (1) adding `bolt12` to the `Method` enum, (2) implementing a BOLT12-capable Lightning backend (offer creation, offer payment, payment preimage retrieval), (3) adding `/v1/mint/quote/bolt12`, `/v1/mint/bolt12`, `/v1/melt/quote/bolt12`, and `/v1/melt/bolt12` routes, (4) enforcing the pubkey-required MUST on mint quotes, (5) implementing multiple-issuance accounting, and (6) advertising the method in NUT-06.
