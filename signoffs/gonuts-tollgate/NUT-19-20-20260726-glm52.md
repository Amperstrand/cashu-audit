| M20-6 | Mint info: `"20": {"supported": <bool>}` | 20.md L210-216 |

### Spec Message Format (M20-3) — CRITICAL

The spec defines the exact binary format for `msg_to_sign` (20.md L109-123):

```
msg_to_sign = b"Cashu_MintQuoteSig_v1"
              || len32(quote) || quote
              || for each output i (in request order):
                   len32(amount_i) || amount_i
                   || len32(B_i)   || B_i
```

Where:
- `b"Cashu_MintQuoteSig_v1"` — domain-separation tag as raw ASCII bytes, **not** length-prefixed
- `||` — byte concatenation
- `len32(x)` — 32-bit (4-byte) big-endian length of byte array `x`
- `quote` — UTF-8 quote id string, raw bytes
- `amount_i` — output amount as canonical minimal big-endian bytes (e.g. `0` → empty, `1` → `0x01`, `256` → `0x0100`)
- `B_i` — raw byte representation of blinded message (e.g. 33-byte compressed secp256k1), decoded from hex

### Findings

#### F-1: Message Format Completely Non-Spec (FAIL)
- **Location**: `nut20.go:17-20` (sign), `nut20.go:39-42` (verify)
- **Issue**: The code constructs the message to sign as:
  ```go
  msg := quoteId
  for _, bm := range blindedMessages {
      msg += bm.B_
  }
  hash := sha256.Sum256([]byte(msg))
  ```
  This produces `SHA256(quoteId_string + B_1_hexstring + B_2_hexstring + ...)`.

  The spec requires:
  ```
  SHA256(b"Cashu_MintQuoteSig_v1"
         || len32(quote_bytes) || quote_bytes
         || len32(amount_1) || amount_1_bytes || len32(B_1) || B_1_rawbytes
         || len32(amount_2) || amount_2_bytes || len32(B_2) || B_2_rawbytes
         || ...)
  ```

  **Five distinct deviations:**

  | # | Spec Requires | Code Does | Impact |
  |---|--------------|-----------|--------|
  | 1 | Domain separator `b"Cashu_MintQuoteSig_v1"` (19 bytes) | Absent | No domain separation — vulnerable to cross-protocol signature reuse |
  | 2 | `len32(x)` 4-byte big-endian length prefix before each field | Absent | Ambiguous serialization — `quote="AB"` + `B_="CD"` hashes same as `quote="A"` + `B_="BCD"` |
  | 3 | `amount_i` as canonical big-endian bytes | Absent entirely | Amounts not committed to in signature — attacker can swap output amounts without invalidating signature |
  | 4 | `B_i` as raw bytes (decoded from hex) | Hex string used directly | Different byte representation — `[]byte("02ab...")` ≠ `[]byte{0x02, 0xab, ...}` |
  | 5 | Binary concatenation `||` | Go string concatenation `+=` | Strings produce UTF-8 encoding of hex characters, not raw bytes |

- **Impact**: **Critical** — signatures produced by this implementation will NOT verify on any spec-compliant wallet or mint, and vice versa. The implementation is self-consistent (sign and verify use the same wrong format), so it works in a closed gonuts-to-gonuts flow, but is **non-interoperable** with the broader Cashu ecosystem.
- **Security concern**: Without the domain separator and length prefixes, the signature scheme is vulnerable to collision attacks across different quote IDs and blinded message sets. Without `amount_i` in the signed message, an attacker who obtains a valid signature for one set of outputs could potentially substitute different amounts.
- **Fix**: Rewrite `SignMintQuote` and `VerifyMintQuoteSignature` to construct the message per spec:
  ```go
  func buildMsgToSign(quoteId string, outputs cashu.BlindedMessages) []byte {
      var buf bytes.Buffer
      buf.WriteString("Cashu_MintQuoteSig_v1")

      quoteBytes := []byte(quoteId)
      len32 := make([]byte, 4)
      binary.BigEndian.PutUint32(len32, uint32(len(quoteBytes)))
      buf.Write(len32)
      buf.Write(quoteBytes)

      for _, bm := range outputs {
          amountBytes := canonicalBigEndian(bm.Amount)
          binary.BigEndian.PutUint32(len32, uint32(len(amountBytes)))
          buf.Write(len32)
          buf.Write(amountBytes)

          bBytes, _ := hex.DecodeString(bm.B_)
          binary.BigEndian.PutUint32(len32, uint32(len(bBytes)))
          buf.Write(len32)
          buf.Write(bBytes)
      }
      return buf.Bytes()
  }
  ```

**NUT-20 Verdict: FAIL** — The integration plumbing (pubkey parsing, storage, signature requirement, error handling, mint info) is all correct. But the core cryptographic message format is completely wrong, producing signatures that are non-interoperable and cryptographically weaker than specified.
