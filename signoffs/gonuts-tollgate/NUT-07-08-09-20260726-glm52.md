## 3. NUT-08: Overpaid Lightning Fees

### Spec MUSTs Extracted

| # | MUST Requirement | Source |
|---|-----------------|--------|
| M08-1 | Wallet includes blank outputs = `max(ceil(log2(fee_reserve)), 1)` | 08.md L15, L19-25 |
| M08-2 | Mint returns `change` field ONLY IF outputs provided AND inputs > total_paid - fees | 08.md L37 |
| M08-3 | Mint decomposes overpaid fees into `2^n` sums | 08.md L39 |
| M08-4 | Mint **MUST** return all blind signatures with value > 0 in same order, omit value-0 | 08.md L43 |
| M08-5 | `PostMeltBolt11Request` includes `outputs` field | 08.md L56-61 |
| M08-6 | `PostMeltQuoteBolt11Response` includes `change` field | 08.md L67-79 |
| M08-7 | Mint info: `"8": {"supported": true}` | 08.md L139-147 |

### Verification

| # | Requirement | Status | Evidence |
|---|------------|--------|----------|
| M08-1 | Blank outputs calculation | **PASS (wallet)** | `wallet/wallet.go:1798-1803` — `calculateBlankOutputs`: `int(math.Max(math.Ceil(math.Log2(float64(feeReserve))), 1))` — exact match to spec formula; called at `wallet.go:1082` |
| M08-2 | Mint processes blank outputs | **FAIL (mint)** | `mint/mint.go:774` `MeltTokens` — `meltTokensRequest.Outputs` is never read; no overpaid fee calculation; no `change` signatures generated |
| M08-3 | Decompose overpaid into 2^n | **FAIL (mint)** | Not implemented — no decomposition logic anywhere in mint code |
| M08-4 | Return non-zero signatures in order | **N/A** | Cannot apply — mint doesn't process outputs |
| M08-5 | Request struct has `outputs` | **PASS** | `cashu/nuts/nut05/nut05.go:75` — `Outputs cashu.BlindedMessages json:"outputs,omitempty"` in `PostMeltBolt11Request` |
| M08-6 | Response struct has `change` | **PASS** | `cashu/nuts/nut05/nut05.go:67` — `Change cashu.BlindedSignatures json:"change,omitempty"` in `PostMeltQuoteBolt11Response`; wallet reads it at `wallet.go:1141` |
| M08-7 | Mint info setting | **PASS (honest)** | `mint/mint.go:1519` — `Nut08: nut06.Supported{Supported: false}` — correctly advertises as **not supported** |

### Code Notes

The wallet side (`wallet.go:1081-1093`) correctly:
1. Calculates blank output count via `max(ceil(log2(fee_reserve)), 1)` (L1082)
2. Generates blank blinded messages with `split := make([]uint64, numBlankOutputs)` (L1083)
3. Includes them in the melt request: `Outputs: outputs` (L1092)
4. Processes returned change signatures: `meltBolt11Response.Change` (L1141-1160)

The mint side ignores the `Outputs` field entirely. The `change` field in the response struct exists but is never populated by the mint (server.go:689-698 constructs the response without setting Change).

Since the mint correctly advertises `Nut08: {Supported: false}`, this is **not a spec violation** — the mint honestly declines to support the feature. A spec-compliant wallet would see `supported: false` and not send blank outputs. The wallet implementation sends them anyway, which is harmless (the mint ignores them).

**NUT-08 Verdict: WARN** — Wallet implementation is spec-compliant. Mint does not implement NUT-08 and correctly advertises this. No interoperability harm.

## 6. Findings

### F-1: NUT-08 Mint-Side Not Implemented (WARN)
- **Location**: `mint/mint.go:774` `MeltTokens`
- **Issue**: The `Outputs` field from `PostMeltBolt11Request` is never read. No overpaid fee calculation, no change signature generation.
- **Impact**: Low — mint correctly advertises `Nut08: {Supported: false}`. Wallets that check the info endpoint won't send blank outputs.
- **Fix**: Implement `overpaid_fees = input_amount - fees - total_paid` decomposition into `2^n` sums, sign blank outputs, return in `change` field.

### F-2: NUT-07 Pending Quote Sync (Positive Finding)
- **Location**: `mint/mint.go:1035-1043`
- **Note**: The checkstate implementation goes beyond the spec by actively syncing pending melt quotes with the Lightning backend before returning states. This ensures `PENDING` proofs that have actually settled are correctly marked as `SPENT`.
