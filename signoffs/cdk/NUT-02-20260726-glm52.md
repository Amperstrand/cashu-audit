## Detailed Verification

### MUST-1, MUST-2, MUST-3: Active keyset enforcement (PASS — library level)

The `cashu` crate provides correct primitives for active-keyset filtering:

- `KeySetInfo.active: bool` — non-optional boolean field (nut02.rs:539). Matches spec JSON `"active": <bool>`.
- `KeySetInfosMethods` trait with `.active()` iterator filter (nut02.rs:555–571):
  ```rust
  fn active(&self) -> impl Iterator<Item = &KeySetInfo> + '_ {
      self.iter().filter(|k| k.active)
  }
  ```
- `KeySet.active: Option<bool>` (nut02.rs:495) with `skip_serializing_if = "Option::is_none"` — used in `/v1/keys` response (NUT-01 cross-reference).

Enforcement of "at least one active keyset" and "sign only from active keysets" is a **mint runtime concern** (cdk-mintd), not the type library. The library provides all necessary tooling. **PASS.**

### MUST-4: Fee calculation (PASS)

Spec formula (L46–51):
```python
def fees(inputs: List[Proof]) -> int:
    sum_fees = sum(keysets[proof.id].input_fee_ppk for proof in inputs)
    return (sum_fees + 999) // 1000
```

CDK implementation in `fees.rs:46–48`:
```rust
let total_fee = (sum_fee.checked_add(999).ok_or(Error::AmountOverflow)?)
    .checked_div(1000)
    .ok_or(Error::AmountOverflow)?;
```

**Exact match.** The `(x + 999) / 1000` integer division is mathematically equivalent to `ceil(x / 1000)` for non-negative integers, matching the spec's recommended approach (L53).

Spec example verification (L33): 3 inputs at 100 ppk → 300 ppk → `ceil(0.3) = 1 sat`. 1–10 inputs = 1 sat, 11–20 = 2 sat.

Test `test_fee_calculation_with_ppk_100` (fees.rs:226–263) confirms:
- 10 proofs → 1 sat (`ceil(1000/1000)`)
- 11 proofs → 2 sats (`ceil(1100/1000)`)

Multi-keyset fee summing (spec L55): "transactions can spend inputs from different keysets, the sum considers the fee for each Proof indexed by the keyset ID individually." Code (fees.rs:30–44) iterates `HashMap<Id, u64>` of proof counts per keyset, multiplies by per-keyset ppk, sums. **Correct.**

Overflow protection via `checked_add`/`checked_mul` is a robustness improvement beyond the spec. **PASS.**

### MUST-5: input_fee_ppk omission from preimage (PASS)

| Step | Spec | Code | Match |

| 3 | Append "\|unit:{unit}" | `data.push_str(&format!("\|unit:{}", unit))` | Yes |
| 4 | Append "\|input_fee_ppk:{fee}" if non-zero | `if input_fee_ppk > 0 { ... }` | Yes |

| 7 | Prefix with "01" | `version: KeySetVersion::Version01` | Yes |

## Response Format Verification

### `GET /v1/keysets` — `KeysetResponse` (PASS)

Spec response (L143–155):
```json
{"keysets": [{"id":..., "unit":..., "active":..., "input_fee_ppk":..., "final_expiry":...}]}
```

Code (nut02.rs:478–484, 531–549):
```rust
pub struct KeysetResponse {
    #[serde_as(as = "VecSkipError<_>")]
    pub keysets: Vec<KeySetInfo>,
}

pub struct KeySetInfo {
    pub id: Id,
    pub unit: CurrencyUnit,
    pub active: bool,
    #[serde(deserialize_with = "deserialize_input_fee_ppk", default)]
    pub input_fee_ppk: u64,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub final_expiry: Option<u64>,
}
```

- `input_fee_ppk`: null → 0 via custom deserializer. Spec L157: "If input_fee_ppk is not given, we assume it to be 0." **Correct.**
- `final_expiry`: Optional, omitted from JSON when None. Spec L122: "MAY be omitted or null." **Correct.**
- `active`: non-optional `bool`. Matches spec `"active": <bool>`. **Correct.**

Test `test_default_input_fee_ppk_is_zero` (nut02.rs:1414–1425) confirms both missing-field and explicit-null cases default to 0.

## Observations (Non-Blocking)

### OBS-1: Stale doc comment on `v2_from_data` (Low severity)

**Location:** nut02.rs:170–177

The doc comment does not match the spec algorithm or the actual code:

| Doc Comment Says | Spec/Code Actually Does |
|---|---|
| "concatenate all public keys to one byte array" | Concatenates `"amount:pubkey_hex"` pairs separated by `","` |
| `"unit:sat"` (no pipe) | `\|unit:sat` (with pipe prefix) |
| (no mention of input_fee_ppk step) | Appends `\|input_fee_ppk:{fee}` when non-zero |
| `"final_expiry:..."` (no pipe) | `\|final_expiry:{val}` (with pipe prefix) |
| "take the first 31 bytes" | Takes full 32 bytes (`STRLEN_V2 = 64` hex = 32 bytes) |

**The code is correct** (verified against spec test vectors). Only the documentation is stale. Recommend updating the doc comment to match spec L65–72.

### OBS-2: `VecSkipError` on response deserialization (Low severity)

**Location:** nut02.rs:482, nut01/mod.rs:147

Both `KeysetResponse.keysets` and `KeysResponse.keysets` use `#[serde_as(as = "VecSkipError<_>")]`, which silently drops array elements that fail deserialization rather than returning an error. If a mint sends a malformed keyset entry, the wallet would silently lose track of that keyset.

This is a deliberate robustness choice (fail-open rather than fail-closed), but it could mask mint bugs or cause wallets to miss keyset rotations. Not a spec violation — the spec does not mandate error behavior on malformed responses.

### OBS-3: Redundant check in `verify_id` (Negligible)

**Location:** nut02.rs:519–524

```rust
ensure_cdk!(u32::from(keys_id) == u32::from(self.id), Error::IncorrectKeysetId);
ensure_cdk!(keys_id == self.id, Error::IncorrectKeysetId);
```

The first check (NUT-13 short ID equality) is strictly subsumed by the second (full ID equality). The redundancy is harmless but unnecessary.
