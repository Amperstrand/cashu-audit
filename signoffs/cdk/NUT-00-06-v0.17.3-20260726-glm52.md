## Executive Summary

**Verdict: PASS — all NUT-00 through NUT-06.**

CDK v0.17.3 carries 32 greatspectations spec-quote comments across the NUT-00..06 source files (down from 51 in the v0.15.1 experiment). The reduction is **deliberate and correct**: v0.17.3 quotes only MUST-level spec requirements, eliminating the SHOULD-level and informational quotes that inflated v0.15.1's count. NUT-03 correctly drops to 0 quotes (the spec defines no MUSTs). All 32 quotes are verbatim spec text, correctly placed at the code elements they describe.

One carry-forward deviation persists (F-1, Low): `Id::from_short_keyset_id` returns the first matching keyset on ambiguity instead of failing as NUT-00 L300 requires. The quote at `nut02.rs:264` makes this gap visible. Between v0.15.1 and v0.17.3, the function gained version-aware matching and prefix-length validation (fixing a panic regression), but the ambiguity check was not added.

**No blockers. No regressions. One carry-forward Low finding (F-1). Two informational observations (F-2, F-3).**

#### Finding F-1: Ambiguous Short Keyset ID (Carry-Forward, Low)

**Location:** `nut02.rs:264-295` (`Id::from_short_keyset_id`)  
**Spec:** NUT-00 L300: *"If a short keyset ID resolves to more than one known full keyset ID, the identifier is considered ambiguous. In this case, the wallet **MUST** fail token parsing and return an error."*

The code at L283-292 iterates keysets and returns `Ok(keyset_info.id)` on the **first** prefix match. The inline comment at L284 explicitly states: *"We return the first match or error"*. No count of matches is maintained; no ambiguity error is raised.

**Severity:** Low. Short keyset IDs use 7-byte V2 prefixes (56 bits). Collision probability among <10 active keysets is negligible (~2^-53). The deviation is a spec-letter gap, not a practical vulnerability.

**v0.15.1 → v0.17.3 change:** The function gained a version check (`keyset_info.id.version == KeySetVersion::Version01`) and switched from slice comparison to `starts_with()`, fixing a panic regression when V2 short IDs were checked against V1 keysets. The ambiguity detection was **not** added.

#### Note: MintVersion Multi-Slash (Observation)

The strict 2-part check is spec-compliant but could reject legitimate version strings containing slashes. **Not a finding** — the behavior matches the spec letter.

## Recommendations

### Short-term (for CDK)

1. **F-1**: Decide whether to implement ambiguity detection in `Id::from_short_keyset_id` (count matches, error if >1) or document as accepted deviation. The quote at `nut02.rs:264` makes the gap visible — closing it would complete the audit loop.
2. **F-3**: Add 3-4 NUT-05 quotes for QuoteState values and melt quote response format fields to bring drift-detection coverage in line with other NUTs.

### Medium-term (for greatspectations)

3. The v0.17.3 quote discipline (MUST-only) is a significant improvement over v0.15.1. Consider documenting this as a convention: *"Quote only RFC 2119 MUST/MUST NOT requirements; SHOULD/MAY are excluded."*
4. The `hash_to_curve` domain separator (`dhke.rs`) remains the most critical unquoted algorithm in the Cashu protocol. Consider adding a quote outside the `nut00/` directory to protect it.
