## Check Results

### M1: Batch check response order matches request order — PASS

**Evidence**:
- `check_mint_quotes` (`issue/mod.rs:586-627`) iterates `quote_ids` in input order, pushing each response to a `Vec` in the same order (line 614: `responses.push(quote.try_into()?)`).
- The HTTP handler `post_batch_check_mint_quote` (`custom_handlers.rs:341-394`) serializes the Vec directly, preserving order.
- Response type is `Vec<MintQuoteResponse<QuoteId>>` — positional array, not keyed.

### M2: Unknown quote_id in batch check rejects entire request — PASS

**Evidence**:
- `check_mint_quotes` (`issue/mod.rs:606-610`): `get_mint_quote(quote_id)` returns `Error::UnknownQuote` on `None`. Early return aborts before any response is constructed.
- All-or-nothing semantics confirmed: the error propagates as `Err`, no partial response is returned.

### M3: Unparseable quote_id rejects entire request — PASS

**Evidence**:
- HTTP handler deserializes body as `Json<BatchCheckMintQuoteRequest<QuoteId>>` (`custom_handlers.rs:345`). `QuoteId` is a strongly-typed UUID wrapper.
- Invalid UUID format fails at the serde deserialization layer → axum returns HTTP 400 automatically before handler logic executes.
- No path exists for a malformed quote ID to reach the business logic.

### M4: All quotes MUST match URL method; mixed methods rejected — PASS

**Evidence** (two-layer defense):
- **HTTP layer**: `validate_mint_quote_methods` (`custom_handlers.rs:111-127`) fetches each quote's payment method via `get_mint_quote_method` and compares against URL path method. Returns `Error::InvalidPaymentMethod` on mismatch.
- **Core layer**: `process_mint_request` (`issue/mod.rs:707-716`) cross-checks all quotes against the first quote's method. Returns `Error::InvalidPaymentMethod` on any mismatch.
- Called for both batch check (`custom_handlers.rs:356`) and batch mint (`custom_handlers.rs:697` via `validate_mint_request_route`).
- Test: `cache_post_batch_mint_rejects_cached_url_method_quote_method_mismatch` (`custom_handlers.rs:1043`) and `post_batch_check_mint_quote_rejects_url_method_quote_method_mismatch` (`custom_handlers.rs:1080`).

### M5: Response signatures one-per-output in order — PASS

**Evidence**:
- `MintResponse { signatures: all_blind_signatures }` (`issue/mod.rs:991-993`) where `all_blind_signatures` is produced by `self.blind_sign(input.outputs().to_vec())` (line 896).
- `blind_sign` processes outputs in the order provided, returning signatures in matching order.
- The response JSON is `{"signatures": [...]}` — matches spec line 119-123.

### M6: Non-empty batch — PASS

**Evidence**:
- `MintInput::validate()` (`issue/mod.rs:54-56`): `if batch.quotes.is_empty() { return Err(Error::UnknownQuote); }`
- Also enforced for batch check: `check_mint_quotes` (`issue/mod.rs:594-596`): `if quote_ids.is_empty() { return Err(Error::UnknownQuote); }`

### M7: Unique quotes — error code 11016 — PASS

**Evidence**:
- `MintInput::validate()` (`issue/mod.rs:58-61`): HashSet uniqueness check → `Error::DuplicateQuoteIds`.
- Error code mapping (`error.rs:1422`): `ErrorCode::DuplicateQuoteIds => 11016`. Matches spec.
- Reverse mapping (`error.rs:1373`): `11016 => Self::DuplicateQuoteIds`.
- Also enforced in batch check path (`issue/mod.rs:598-601`).
- Test: `test_process_batch_mint_duplicate_quotes` (`issue/mod.rs:1527-1580`) asserts `Error::DuplicateQuoteIds`.

### M8: All quote IDs MUST exist in database — PASS

**Evidence**:
- `process_mint_request` (`issue/mod.rs:691-696`): fetches each quote via `get_mint_quote`, returns `Error::UnknownQuote` on `None`.
- Same pattern in batch check (`issue/mod.rs:606-610`).

### M9: Payment method consistency with URL path — PASS

**Evidence**: See M4. Both HTTP and core layers validate method consistency. The HTTP layer explicitly checks URL `{method}` against each quote's stored method.

### M10: Currency unit consistency — PASS

**Evidence**:
- `process_mint_request` (`issue/mod.rs:717-725`): iterates all quotes, checks `quote.unit != batch_unit` → `Error::UnitMismatch`.
- `batch_unit` is derived from the first quote (`issue/mod.rs:706`).
- Cross-checks outputs unit too (line 839: `ensure_cdk!(outputs_amount.unit() == &batch_unit, Error::UnsupportedUnit)`).

### M11: Quote state MUST be PAID (or mintable for bolt12) — PASS

**Evidence**:
- State validation loop (`issue/mod.rs:746-762`):
  - `MintQuoteState::Unpaid` → `Error::UnpaidQuote`
  - `MintQuoteState::Issued` → `Error::IssuedQuote` (with bolt12 multi-mint warning if amount_paid > amount_issued)
  - `MintQuoteState::Paid` → proceeds
- Bolt12 multi-mint support: `amount_mintable()` (`cdk-common/src/mint.rs:724-728`) computes `amount_paid - amount_issued`. For bolt12 with remaining mintable amount, the quote stays in PAID state (since `amount_paid > amount_issued`), allowing continued minting.
- Zero-mintable check (`issue/mod.rs:796-799`): `expected_amount == 0` → `Error::UnpaidQuote`.
- Test: `test_process_batch_mint_unpaid_quote` (`issue/mod.rs:1376-1449`).

### M12: Amount balance (outputs vs quote_amounts) — PASS (with minor deviation)

**Evidence**:
- Phase 3 validation (`issue/mod.rs:838-893`):
  - `outputs_amount > total_expected_value` → `Error::TransactionUnbalanced` (always rejected). ✅
  - `outputs_amount < total_expected_value` → rejected for batch (partial only allowed for single non-bolt11, line 878: `!input.is_batch() && !batch_method.is_bolt11()`).
- For bolt11 batch: outputs must exactly equal sum of quote amounts. ✅ (spec: "MUST equal")
- Tests: `test_process_batch_mint_inflated_outputs` (rejects over), `test_process_batch_mint_mismatched_amounts_length`.

**Minor deviation**: For bolt12 batch, spec says outputs "MUST NOT exceed" quote_amounts (implying less-than is valid). CDK requires exact equality for batch (`is_partial_allowed` is false for batch). This is stricter than spec — not a security issue, but prevents a valid use case where a wallet intentionally mints less than declared. **Severity: Low (cosmetic over-strictness, no security impact).**

### M13: Signature array length, locked/unlocked rules — PASS

**Evidence**:
- Length check: `MintInput::validate()` (`issue/mod.rs:69-73`): `sigs.len() != batch.quotes.len()` → `Error::SignatureMissingOrInvalid`.
- Locked quote requires signature: `entry.signature.as_ref().ok_or(Error::SignatureMissingOrInvalid)?` (`issue/mod.rs:817-820`).
- Unlocked quote rejects signature: `else if entry.signature.is_some() { return Err(Error::SignatureMissingOrInvalid); }` (`issue/mod.rs:827-829`).

### M14: Any validation failure rejects entire batch — PASS

**Evidence**:
- Validation is organized in phases (Phase 1: structure, Phase 2: per-quote, Phase 3: amounts) all BEFORE any database write.
- Phase 4 (signing) and Phase 5 (DB transaction) only execute after all validation passes.
- Database updates use a single transaction (`issue/mod.rs:904: tx = begin_transaction()`) with `tx.commit()` at line 978. If any quote fails mid-transaction, the error propagates and the transaction is never committed (dropped on scope exit = rollback).
- Test: `test_process_batch_mint_atomicity` (`issue/mod.rs:1657-1774`) — batch with one already-issued quote fails, second quote remains in PAID state (unchanged).

### M15: Signature array length equals quote array length — PASS

**Evidence**: Same as M13 length check. Type `Option<Vec<Option<String>>>` (`nut29.rs:72`) allows the field to be omitted entirely when all quotes are unlocked (spec line 220: "Optional: May be omitted entirely if all quotes are unlocked").

### M16: signatures[i] corresponds to quotes[i] — PASS

**Evidence**:
- `quote_entries()` (`issue/mod.rs:89-106`) zips signatures with quotes by enumerate index: `batch.signatures.as_ref().and_then(|sigs| sigs.get(i).cloned()).flatten()`.
- Positional correspondence is structurally guaranteed by the index-based iteration.

### M17: Locked quotes include signature string — PASS

**Evidence**: See M13. When `mint_quote.pubkey` is `Some`, signature extraction is mandatory (`issue/mod.rs:811-825`). Verification via `verify_quote_signature` uses the full batch outputs array.

### M18: Unlocked quotes signatures[i] is null — PASS

**Evidence**: The type `Vec<Option<String>>` allows null entries (`nut29.rs:72`). CDK also actively rejects non-null signatures for unlocked quotes (`issue/mod.rs:827-829`), which is stricter than spec (spec permits null but doesn't explicitly forbid a stray value).

### M19: Any invalid signature rejects entire batch — PASS

**Evidence**:
- Per-quote signature verification loop (`issue/mod.rs:811-825`): any verification failure → `Error::SignatureMissingOrInvalid`, immediate return.
- Verification happens in Phase 2 (before any signing or DB writes), so no partial state can occur.
- `verify_quote_signature` (`nut29.rs:111-139`) parses signature, computes message, and verifies against pubkey.

### M20: Signature message format — PASS

**Evidence**:
- `mint_quote_msg_to_sign` (`nut20.rs:45-59`) constructs the message exactly as specified:
  - `b"Cashu_MintQuoteSig_v1"` raw, NOT length-prefixed ✅ (line 50)
  - `len32(quotes[i]) || quotes[i]` via `append_len_prefixed(quote_id.as_bytes())` ✅ (line 51)
  - Per output: `len32(amount_j) || amount_j || len32(B_j) || B_j` ✅ (lines 53-56)
- `amount_to_minimal_bytes` (`nut20.rs:26-38`): `0` → empty, `1` → `[0x01]`, `256` → `[0x01, 0x00]`. Matches spec canonical big-endian. ✅
- `append_len_prefixed` (`nut20.rs:40-43`): `(bytes.len() as u32).to_be_bytes()` = 4-byte big-endian length. Matches `len32`. ✅
- `to_bytes()` on `PublicKey`: compressed secp256k1 (33 bytes). Matches spec. ✅
- Test vector verification (`nut29.rs:194`): exact hex match of message bytes, plus SHA256 hash match. Confirmed against spec-derived value.

### M21: NUT-06 advertising — PASS

**Evidence**:
- `Nuts` struct (`nut06.rs:338-339`): `#[serde(skip_serializing_if = "nut29::Settings::is_empty")] pub nut29: nut29::Settings`.
- Serialized under key `"29"` (serde default field name).
- `Settings` (`nut29.rs:27-34`): `max_batch_size: Option<u64>`, `methods: Option<Vec<String>>`, both `skip_serializing_if = "Option::is_none"`.
- Matches spec example (lines 278-286): `{"29": {"max_batch_size": 100, "methods": ["bolt11", "bolt12"]}}`.
- Builder method `with_batch_minting` populates settings. Enforced at runtime: batch mint rejected if settings empty (`issue/mod.rs:659-661`) and if method not in configured list (`issue/mod.rs:728-735`).
- Tests: `test_process_batch_mint_enforces_max_batch_size`, `test_process_batch_mint_enforces_allowed_methods`, `test_process_batch_mint_rejects_when_nut29_not_configured`.

## Findings & Notes

### Finding 1: Bolt12 batch requires exact amount equality (stricter than spec) — Low

**Location**: `issue/mod.rs:875-893`

The spec (line 196) states for bolt12: outputs "MUST NOT exceed" the sum of `quote_amounts`. This permits a wallet to mint less than the declared amount. CDK's `is_partial_allowed` check (line 878) is `!input.is_batch() && !batch_method.is_bolt11()`, meaning batch requests always require exact equality regardless of method.

**Impact**: A wallet using bolt12 batch minting that intentionally provides fewer outputs than the declared `quote_amounts` would be rejected. This is a valid spec-permitted scenario that CDK disallows. No security impact — CDK is conservative.

**Recommendation**: Consider relaxing to allow `outputs <= total_expected` for bolt12 batch, matching single-quote behavior. Low priority since current bolt12 batch usage typically mints the full declared amount.

### Finding 2: Legacy signature format fallback — Informational

**Location**: `nut29.rs:123-136`

`verify_quote_signature` first tries the domain-separated message format (spec-compliant), and on failure falls back to the legacy format (`legacy_mint_quote_msg_to_sign`). The legacy format is `quote_id || hex(B_j)` without domain separation or length prefixing.

**Impact**: Both formats bind the same semantic data (quote ID + all outputs), so accepting either does not weaken the signature's commitment. The fallback exists for backwards compatibility with wallets that haven't upgraded. A `tracing::warn!` is logged on every legacy acceptance for observability.

**Assessment**: Not a security vulnerability. The legacy format is a subset commitment (lacks amount binding in some interpretations), but CDK's legacy function does include both quote_id and blinded_secret. The domain-separated format is strictly preferred. Acceptable for production.

### Finding 3: Batch check validates uniqueness (stricter than spec) — Informational

**Location**: `issue/mod.rs:598-601`

The spec's batch check section (Section 1) does not explicitly require uniqueness validation — it only says quotes are "unique" in the request description (line 29). CDK's `check_mint_quotes` actively rejects duplicates with `Error::DuplicateQuoteIds`. This is a reasonable defensive measure and does not conflict with the spec.
