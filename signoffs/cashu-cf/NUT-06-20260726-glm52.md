## Findings

### Finding 1: Contact raw-string fallback deviates from spec type (WARN)
- **Severity**: Low
- **Location**: `src/mint/info.ts:165-167`
- **Description**: When `MINT_CONTACT` is a non-JSON string, the code returns it as-is (a `string`), not as an array of contact objects. Spec §95 states: "contact is an array of contact objects. A contact object consists of two fields."
- **Impact**: None in production — all `wrangler.toml` environments set `MINT_CONTACT` as a JSON array string (e.g., `wrangler.toml:90`). The raw-string branch (`contactRaw`) is unreachable with current configs. However, it represents a latent type contract violation if an operator sets `MINT_CONTACT` to a plain string.
- **Recommendation**: Either coerce non-JSON strings into `[{ method: "email", info: "<string>" }]` or drop the raw-string fallback entirely and require JSON array input.

### Finding 2: Placeholder contact data persists in all environments (WARN)
- **Severity**: Low (operational, not a code defect)
- **Location**: `wrangler.toml:90` (testnut), `:303` (nofeestestnut), `:424` (paytofakewallet), `:539` (rugs), `:717` (rugs01)
- **Description**: ISSUE-020 is marked `done` in AGENTS.md, but its acceptance criterion 1 states: "Either real contact info is populated per env, OR the placeholder entries are removed." Neither condition is met — all environments still contain placeholder data: `contact@me.com`, `@me`, `npub1337`, `uncle_rick` (internal nickname), `pavol` (internal nickname). The code fix (configurable contact, `INFO_HIDE_CONTACT` flag, empty array support) was delivered, but the operator has not updated the data.
- **Impact**: Wallets that surface contact info (Cashu.me, Enuts) display fake data. A user emailing `contact@me.com` or messaging `npub1337` reaches the wrong party. Not a spec violation (contact is optional and the array format is valid), but a data quality issue.
- **Recommendation**: Operator should either replace placeholder entries with real contact info or remove them (set `MINT_CONTACT = "[]"` or set `INFO_HIDE_CONTACT = "true"`).
