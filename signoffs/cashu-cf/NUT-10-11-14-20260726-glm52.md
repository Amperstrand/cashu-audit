## Findings

### Finding 1: Duplicate tag enforcement is partial (WARN)
- **Severity**: Low
- **Location**: spending-conditions.ts:432 (pubkey dedup) vs 171-178 (getTag)
- **Description**: Only `pubkeys` tag duplicates are rejected. Other tags (`locktime`, `sigflag`, `n_sigs`, `refund`) use `getTag()` which silently returns the first match. NUT-11 L85 states: "Each of the above tags may appear exactly ONCE... MUST be rejected as unspendable."
- **Impact**: Low — an attacker can't exploit this (first-match behavior is deterministic), but it deviates from spec letter.
- **Recommendation**: Add a `validateTagUniqueness()` function that checks all tags for duplicates before processing.

### Finding 2: SIG_ALL tries 10 candidate message formats (WARN)
- **Severity**: Info
- **Location**: spending-conditions.ts:759-804
- **Description**: `verifySigAll` builds 10 candidate messages (different sortings, different field combinations) and tries each until one verifies. This is a pragmatic compatibility hack for divergent wallet implementations, but it weakens the signature verification contract — any of the 10 formats is accepted.
- **Impact**: Info — necessary for real-world wallet compatibility, but worth documenting.
- **Recommendation**: Already documented in code comments. No action needed unless a specific format is found to be insecure.
