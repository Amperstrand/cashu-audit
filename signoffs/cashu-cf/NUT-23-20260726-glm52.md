## Observations (Non-Blocking)

### OBS-1: `method` field omitted from all bolt11 responses
**Location**: mint.ts:416-427 (mint quote), melt.ts:1014-1023 (melt quote), melt.ts:1225-1234 (melt status), melt.ts:3212-3223 (melt result)
**Spec ref**: NUT-23 L25-37, L161-172, L189-203 — all response type definitions include `"method": "bolt11"`
**Impact**: Low. The `method` field is defined in the spec's JSON type examples but has no associated MUST language. The endpoint URL path (`/v1/mint/quote/bolt11`, `/v1/melt/quote/bolt11`, `/v1/melt/bolt11`) already conveys the method unambiguously. cashu-ts types likely mark `method` as optional (the code compiles without it). No known wallet implementation depends on this field in the response body.
**Recommendation**: Add `method: 'bolt11'` to all four response construction sites for full spec conformance. One-line change per site.

### OBS-2: NUT-05 method settings strip `options` entirely
**Location**: info.ts:131-135
**Spec ref**: NUT-23 L259-271 — `MeltMethodSetting` example shows `options: { amountless: true }`
**Impact**: None currently — amountless is not implemented and the spec marks it optional. However, stripping `options` prevents future features from being advertised without code changes to the info builder.
**Recommendation**: Change `info.ts:131-135` to preserve `options` (or default to `{}`) instead of deleting it, to allow future melt-method options.

### OBS-3: Mint quote `description` fallback to `quote {quoteId}`
**Location**: mint.ts:341
**Detail**: When the wallet does not provide a `description`, the code sets `invoiceDescription = description ?? \`quote ${quoteId}\``. This is used for sibling mint detection (L338-339 comment). This is a deliberate operational choice, not a spec deviation — the spec allows the mint to set any description on the invoice it creates. Wallets that supply their own `description` will have it used instead. Non-blocking, but worth documenting as it affects invoice metadata.
